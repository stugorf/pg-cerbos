Policy Registry Graph Query Flow

Graph Query Authorization Lifecycle

Graph queries enter the policy registry through either direct execution or natural language generation. The backend resolves the selected language route, retrieves that backend's schema, analyzes the query, asks Cerbos for an authorization decision, and only then executes against PuppyGraph, Neo4j, or Fuseki.

HTML version of GRAPH_QUERY_LIFECYCLE.md. Diagrams on this page are built with HTML and CSS.

Executive Summary

Pre-execution enforcement Every graph query is analyzed and authorized before any backend runs it.
Route-specific schema NLI and validation use the schema from the selected language route.
Shared AML data Postgres AML tables are the canonical data source for PuppyGraph, Neo4j, and Fuseki.
Fail closed Analyzer, schema, route, or policy failures reject the query before execution.

Adapter Implementations And Language Parsing

The UI language selector is the route key. The backend passes that language through schema retrieval, natural language generation, analyzer parsing, policy evaluation, and final execution. The adapter layer keeps graph database details out of the FastAPI route handlers.

PuppyGraph Adapter

PuppyGraphEngineAdapter handles cypher and gremlin.

  • Uses the existing PuppyGraph client and the Postgres-backed AML schema mapping.
  • cypher executes through PuppyGraph's openCypher route.
  • gremlin executes through PuppyGraph's Gremlin route.
  • Schema is read from the PuppyGraph configuration so NLI and validation see the mapped labels and edges.
  • Parser/library basis: Cypher is validated with Neo4j/openCypher parser tooling; Gremlin scripts must produce TinkerPop traversal Bytecode.

Neo4j Adapter

Neo4jEngineAdapter handles gql for the Neo4j demo route.

  • Uses the Neo4j Bolt driver configured by NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD, and optional NEO4J_DATABASE.
  • Executes the selected GQL route against synced AML nodes and relationships.
  • Discovers labels, relationship types, and properties from Neo4j for schema-aware NLI and validation.
  • Normalizes Neo4j nodes, relationships, paths, scalars, lists, and maps into JSON-safe result rows.
  • Parser/library basis: GQL is validated with a vendored ANTLR ISO GQL grammar; execution and graph-value normalization use the Python neo4j driver.

Fuseki Adapter

FusekiEngineAdapter handles sparql for the RDF route.

  • Uses Apache Jena Fuseki over HTTP with FUSEKI_URL and FUSEKI_DATASET.
  • Executes SPARQL SELECT queries against synced AML RDF triples.
  • Builds a schema view from RDF classes, predicates, and observed property usage.
  • Converts SPARQL JSON bindings into the shared { results, columns } response shape.
  • Parser/library basis: SPARQL is validated with Apache Jena ARQ QueryFactory; predicate metadata is read from the parsed query pattern.

Lifecycle Diagram

Request to result lifecycle
1. Request intake POST /query/graph or POST /query/graph/natural-language includes the selected language.
2. Resolve route The backend maps language to PuppyGraph, Neo4j, or Fuseki and fetches that route's schema.
3. Generate or validate NLI generates a graph query; direct queries are validated against the selected schema.
4. Analyze query The analyzer returns normalized metadata for labels, edges, traversal depth, filters, and read/write status.
5. Load principal The backend loads user roles and attributes from the policy store.
6. Cerbos decision Cerbos evaluates the cypher_query resource and the authenticated principal.
7a. Deny path Deny or analyzer errors return HTTP 403 or a route-specific validation error.
7b. Allow path The selected adapter executes the query, sanitizes results, and returns timing/chart metadata.

Entry Points

Endpoint Purpose Execution behavior
GET /query/graph/schema?language=... Retrieve schema for the selected graph route. Used by NLI and query validation.
POST /query/graph Execute a direct graph query for cypher, gremlin, gql, or sparql. Fetches schema, analyzes, authorizes, then executes.
POST /query/graph/natural-language Convert natural language to the selected graph language. Returns generated query when execute=false; authorizes and executes when execute=true.

Analyzer Contract

For graph query requests, the backend calls analyze_graph_query(...). When GRAPH_QUERY_ANALYZER_URL is configured, the backend sends the query to the analyzer sidecar. Without the sidecar, graph query execution is rejected with an actionable analyzer error.

Analyzer failures are fail-closed. If analysis is unavailable, incomplete, malformed, or returns an error, the backend rejects the request before Cerbos evaluation and before graph database execution.

Policy Controls

Dimension Examples Current usage
Query type cypher, gremlin, sparql, gql Determines route, analyzer language, and execution adapter.
Read/write classification is_read_only, has_write_operation Writes are denied by policy by default.
Node labels Customer, Account, Transaction, Alert, Case, SAR Used for sensitive node and SAR restrictions.
Relationship types OWNS, SENT_TXN, FLAGS_CUSTOMER, FROM_ALERT Used for sensitive alert relationship restrictions.
Traversal depth 0, 1, 2, 4 Junior/base analysts are limited to 2 hops; seniors to 4.
ABAC filters Team, region, PEP flag, transaction amount threshold Compared to principal attributes such as team, region, and clearance level.
